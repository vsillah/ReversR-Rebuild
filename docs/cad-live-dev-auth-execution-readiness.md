## Executable local rollback evidence

Run from the assigned worktree with lockfile-pinned dependencies:

```sh
node scripts/cad-convex-rollback-compatibility.js
node --test scripts/cad-convex-rollback-compatibility.test.js
```

The fixed-path CLI reads only committed synthetic fixtures and reviewed local
source/dependencies. It accepts no path, credential, environment or live-command
arguments. It emits schema/source/bindings hashes, fixed codes and counts; never
fixture rows, data hashes or raw caught errors. Failure exits nonzero.

[The loader](../scripts/helpers/cad-convex-schema-export.js) transpiles only
`convex/schema.ts` and the pinned Auth 0.0.95 `implementation/types.ts`. It uses
real Convex 1.45.0 schema constructors and TypeScript 6.0.3, with allowlisted schema
imports, no Auth runtime or generated function import, and no environment loader.
The VM limits imports and execution time for trusted reviewed source; it is not
a security sandbox for untrusted code. The SDK's internal export format is pinned;
unknown fields or features fail the model and require review after upgrades.

[rollbackBaseline.json](../offline/cad-convex/rollbackBaseline.json) records the
expanded validators/indexes from the verified base commit, SDK versions and
source/generated-bindings hashes. It is a disabled **source candidate**, never a
verified cloud release. It is deliberately not regenerated by the checker. Source
review is required before replacing the baseline or fixtures; passing by deleting
fixtures, validators, table rows or indexes is unacceptable.

[rollbackFixtures.json](../offline/cad-convex/rollbackFixtures.json) contains 22
explicit synthetic documents across all ten tables, including minimal/populated
Auth records, refresh-token parent links, expired sessions and revoked upload
shapes. Non-Password enum fixtures and unused Auth tables exercise retained schema
shapes; they authorize no method or enrollment. Fake IDs use `fixture:table:key`.
They are not valid provider IDs. Data fields omit provider-owned `_id` and
`_creationTime`; live ID validation, foreign-key existence and system fields are
outside this model. No raw data or private export is accepted as fixture evidence.

[The pure model](../offline/cad-convex/rollbackCompatibility.js) checks:

- Every table is represented in before/proposed/disabled schemas and both fixture
  phases; every optional field has both absent and populated coverage.
- Before-run retained fixtures satisfy the current proposed schema; after-run
  fixtures satisfy the disabled rollback candidate. With no schema delta in this
  slice, both directions deliberately use the same committed synthetic fixture set.
- Existing indexes survive forward changes, and proposed indexes survive rollback,
  with exact name/field order. This is a conservative source check, not remote
  index-build readiness or proof that every runtime query remains supported.
- Unknown validators, staged/search/vector indexes, missing/duplicate tables,
  disabled validation, wrong tagged ID tables and malformed records fail closed.

The result always includes `executable=false`, `liveReady=false` and
`verifiedCloudRelease=null`. `fixtureCompatible=true` means only these supplied
synthetic shapes passed this model. It does not prove compatibility for arbitrary
retained data, SDK runtime validation, deletion cascades, cleanup access, session
revocation, source behavior or a deploy/rollback command. A future schema change
needs independently reviewed before/after fixtures, complete bounded retained-shape
coverage and a compatible disabled source. The current equality/provenance test
intentionally requires review when source or generated bindings drift.

The new sentinel checks cover this model's result objects and fixed-path CLI
argument errors only. They do not fulfill PR #189's required end-to-end diagnostic
sentinel harness across transport success/denial/timeouts/unknown writes/provider
exceptions/cleanup and stdout/stderr/client/receipt/telemetry sinks.
