# Phase 7: unmounted Google identity verification source

This checkpoint adds executable RSA signature verification and a bounded HTTPS transport implementation. It does not install provider trust or invoke a provider. Public production entry points always deny without inspecting inputs, fetching keys or reading configuration. All prior journal, custody, gateway and continuity bytes remain unchanged from `2495a198cb5dc8a450cc7fb874933dc7700eea3a`.

## Verified property and limits

The synthetic-only `verifySignatureAgainstSuppliedTestKeys` function verifies RS256/PKCS1 signatures using Node crypto against supplied public test keys. It compares claims against captured test policy and rechecks time after awaited test-key retrieval. Its only success property is `signatureCheckedAgainstSuppliedTestKeys`. Its immutable result never returns tokens, claims, subjects, email, key data, exception messages or URLs. Google provenance, host qualification, body admission and live readiness remain false. Supplied callbacks, clocks, policies and matching signatures cannot establish actual Google trust, independent custody, a current journal, revocation, an approved deployed commit or `VerifiedContinuity`.

Google service-account ID tokens use Google's signing keys and identify the service account by subject. They are distinct from service-account-signed JWT assertions and access tokens. This module does not obtain tokens, exchange Vercel federation credentials, authorize Cloud Storage, validate Google IAM or implement application role dispatch. [Google token types](https://docs.cloud.google.com/docs/authentication/token-types).

The narrow accepted profile requires exactly `alg`, `kid`, `typ` headers: RS256, bounded key ID and JWT. Claims are restricted to issuer, audience, numeric subject, iat, exp, optional nbf, azp, email and email_verified. Unknown extensions deny. Issuer must be exactly `https://accounts.google.com`; audience must be one exact nonempty string; subject must match the explicit numeric identity. Optional email matching supplements the subject check and requires email_verified true. Optional azp must equal subject. Multi-audience tokens, token-supplied keys/URLs, critical extensions, duplicate JSON property names (including escaped aliases), invalid UTF8 and noncanonical base64url deny. JSON values are parsed with standard JSON APIs; a bounded structural scan detects duplicate names. The profile intentionally rejects otherwise legitimate extension-rich tokens until separately reviewed.

RSA public signing keys require unique kid values, RSA/sig/RS256, modulus bounds 2048-4096 bits and exponent 65537. At most eight keys and 32 KiB of JWKS JSON are accepted. Private or unknown JWK fields deny. Unknown or rotated kid denies with no automatic fetch/refresh retry. Token size is capped at 12 KiB, decoded header at 1 KiB and claims at 6 KiB. Token lifetime is at most one hour. Clock uncertainty is at most one second, and retrieval elapsed time is at most five seconds. Both clock intervals must overlap the elapsed monotonic advance. No clock skew grace extends token expiry.

Test key evidence has an explicit observation time at or before the initial clock lower bound, expires within 60 seconds of observation, and must remain fresh after the await. This is a conservative supplied-snapshot contract, not an assertion that these timestamps came from Google. A future integration must bind request-start/key observation, freshness and trusted clocks explicitly; the transport and verifier are deliberately not wired together.

## Private transport implementation

The only request target is `https://www.googleapis.com/oauth2/v3/certs`, as shown by Google's published OpenID configuration. No live discovery, key retrieval or tokeninfo calls occurred. [Google OpenID Connect documentation](https://developers.google.com/identity/openid-connect/openid-connect).

The private `requestPublicKeys` implementation uses Node HTTPS with normal certificate/hostname validation, TLS 1.2 minimum, a nonshared agent and fixed public Accept headers. There is no auth header, credential lookup, proxy/env discovery, caller-selected endpoint, redirect following, retry loop, key cache or import-time request. Its total five-second deadline covers connection, headers and body; header bytes are capped at 8 KiB and streamed body bytes at 32 KiB. Response status, encoding, cache freshness, duplicate critical headers, declared length, UTF8, JSON and key count are checked. Abort, TLS/socket errors, stalled requests, incomplete responses and limit violations produce a fixed sanitized denial. Successful private transport output is public JWKS bytes only, never identity or custody authority.

Tests expose this otherwise private lexical function only inside a VM harness whose `node:https` is replaced with a mock and whose timers/monotonic clock are controlled. The test harness has no path to real HTTPS. Production `fetchGooglePublicJwks` remains unconditionally disabled. No passed boolean, configuration object or callback opens it. Node crypto generates ephemeral synthetic RSA keys in test memory; no key files or real credentials are read or written.

Cloud Run expects a receiving-service audience or an approved custom audience and appropriate invoker permission. Some forwarding modes strip signatures; that behavior must be resolved before installing this verifier. Neither a valid token nor the shared Google key set establishes that the chosen subject is the approved independently administered custody service. [Cloud Run service authentication](https://docs.cloud.google.com/run/docs/authenticating/service-to-service).

Source-owned parsing and key helpers are captured privately when each module initializes. Replacing their CommonJS exports afterward cannot reinterpret signed claims or bypass transport checks. This does not defend against compromise of the trusted runtime before initialization. Cache directive names are normalized before duplicate checks; any no-cache/no-store directive denies, including qualified values. Duplicate directives, empty segments and quoted max-age values conservatively deny. Mixed-case Max-Age with unquoted decimal seconds is accepted.
