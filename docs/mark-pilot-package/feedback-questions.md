# Structured feedback questions

Capture evidence from a task Mark performed, a decision he made, or a document
he said was missing. Avoid "What did you think?" and other questions that
produce approval without a product requirement.

## Six questions to use live

Use these during the five-minute session. The longer bank below is for follow-up
or synthesis, not for turning the conversation into an interview.

1. Before you trusted this source for quoting, what revision or approval
   evidence would you need beside the file?
2. Which imported fact helps screening, and which one could be mistaken for a
   verified manufacturing value?
3. Show the first feature you would question. What evidence would you ask for
   next?
4. What would you need to know about the IGS-to-STL conversion before the STL
   could enter your workflow?
5. Which boundary from your 2D print process maps best here: source artwork,
   proof, materials and finishing, or production release? Where does that
   comparison break down?
6. If ReversR fixed one thing before another session, which change would remove
   the largest manufacturing-risk ambiguity?

## Session record

Record before the first question:

- session date and facilitator;
- production URL used;
- browser and operating system;
- viewport class: desktop, tablet, or mobile;
- fixture ID: `mark-dispenser-v1`;
- confirmation that no Mark-owned or private file was requested, selected, or
  received;
- recording status and consent, if any.

Do not record a private filename, customer name, part number, drawing number,
contact detail, or confidential screen content.

## Follow-up bank: source trust

1. What is the first document or identifier you would compare with
   `Dispenser.IGS` before using it for a quote?
2. Could you find the filename, format, units, and source fingerprint without
   coaching? Record `yes`, `with prompt`, or `no`, plus the exact point of
   hesitation.
3. Which label could cause someone to confuse file identity with design
   approval? Quote the label and propose replacement wording.
4. What revision, release, or ownership field must appear before this source can
   enter your normal intake process?

## Follow-up bank: geometry and dimensions

5. Ask Mark to locate the units, extents, and connected-component count. Record
   the order in which he looks for them.
6. Which displayed value is useful for screening, and what decision would it
   support?
7. Which displayed value could be misused as a verified manufacturing value?
   Record the misuse and the warning or evidence that would prevent it.
8. What drawing dimensions, datums, tolerances, or feature callouts are missing
   for the next decision?

## Follow-up bank: viewer workflow

9. Give one task: "Show the feature you would question first." Record the first
   control used, whether it worked, any recovery action, and time to completion.
10. Ask Mark to orbit, switch to Move, pan, use a fixed view, zoom, and fit.
    Record any control he could not name or predict before clicking.
11. Did the reference images help him locate a feature, create confusion, or add
    no value? Record the feature and why.
12. If a control failed or felt unclear, classify the result as `blocked`,
    `slow`, `recoverable`, or `cosmetic`. Capture the expected behavior in one
    sentence.

## Follow-up bank: source-to-STL lineage

13. Ask Mark to download or point to the original IGS and derived STL. Could he
    explain which was authoritative and which was for inspection?
14. What conversion evidence would he need: tool and version, tessellation
    settings, tolerance, timestamp, operator, validation result, or something
    else? Rank the first two.
15. Name one task for which the current STL is useful and one task for which he
    would reject it.
16. Does the not-fully-watertight warning change his decision? Record the exact
    next check he would run.

## Follow-up bank: privacy and file handling

17. Before sharing one file he controls, what must ReversR state about purpose,
    storage location, provider access, retention, deletion, and reuse?
18. Who is allowed to approve that file's use, and what proof of authority would
    he expect ReversR to retain?
19. What event should force an immediate stop: unexpected upload, unexpected
    provider call, missing delete receipt, digest mismatch, uncertain outcome,
    or another condition?

## Follow-up bank: decision evidence

20. Ask Mark to choose one outcome: `continue public-fixture research`, `revise
    before another session`, or `stop`. Record the evidence behind the choice.
21. What single product change would remove the largest manufacturing-risk
    ambiguity?
22. What observable result would prove that change worked in a follow-up
    session?
23. Does Mark recommend considering a separately governed file pilot? A `yes`
    records interest only. It does not supply a file, consent, authority,
    execution approval, or manufacturing acceptance.

## Observation note template

Use one row per meaningful event.

| Tour step | Task or question | Mark's action or words | Expected result | Observed result | Severity | Evidence needed next |
| --- | --- | --- | --- | --- | --- | --- |
| Example: traceability | Distinguish IGS from STL | Opened Download and selected STL first | Names IGS as source | Needed prompt | Slow | Put `Original source` before format label |

Keep the note factual. Separate what Mark did from what the facilitator inferred.
