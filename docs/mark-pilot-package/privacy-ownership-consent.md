# Privacy, file ownership, and consent

## Language for the public-fixture session

Read this before starting:

> Today's session uses only the public Dispenser fixture already provided by
> ReversR. Please do not select, upload, email, or show a private CAD file. The
> tour does not activate the private upload path or send this fixture to a
> conversion provider. ReversR may take notes about your actions and feedback,
> but those notes should not contain customer names, private part details, or
> confidential screen content. You can pause or stop the session at any time.

Then ask:

> Are you comfortable continuing with the public fixture under those limits?

Record `yes`, `no`, or `needs clarification`, with the date and facilitator.
Do not infer consent from attendance or from positive product feedback.

## Screen or audio recording

Recording is optional. Ask immediately before recording:

> May I record this public-fixture walkthrough and your comments for internal
> ReversR product review? The recording must not show private files,
> notifications, customer information, or another application. You can decline
> and we can use written notes instead.

Record the answer. If Mark says no, do not record. If private information
appears, stop the recording and quarantine the artifact for Captain-directed
deletion or redaction. Do not continue recording around the exposure.

## File ownership

- Mark keeps all rights he already has in any file he owns or is authorized to
  use. This public-fixture session requests no file and no license from him.
- ReversR provides the approved public Dispenser fixture for this session. The
  repository records source-provider permission to redistribute it for public
  review. That record does not establish every underlying design right or grant
  permission to fabricate the design.
- Feedback notes may inform product decisions. They do not transfer ownership of
  Mark's designs, shop methods, customer work, or confidential manufacturing
  knowledge.
- ReversR should not use Mark's name, company, endorsement, or quotes outside
  the approved pilot record without separate permission.

## What the application keeps in this phase

The tour reads checked-in public assets. It stores tour progress on the current
device so the guide can resume. Closing the tour preserves that progress;
Restart clears the tour checklist and returns to the same public fixture.

This behavior does not prove private-file storage, retention, deletion, or
revocation. No private file should enter this phase, so no private cleanup claim
should be made.

## Consent needed for any later Mark-owned-file pilot

A later file pilot requires a new, written record that names:

- the exact file through a private reference, without putting its path or
  contents in public source;
- Mark's authority to provide it and any customer or employer restrictions;
- the permitted purpose and the questions the run may answer;
- the exact environment, upload route, converter, and any provider that may
  receive file bytes;
- who may access source and derived artifacts;
- retention duration, deletion deadline, deletion owner, and deletion evidence;
- allowed outputs and who may receive them;
- a hard cost and operation cap;
- stop, rollback, unknown-outcome, and no-retry rules;
- whether the file or derived data may be reused, retained for debugging, used
  for training, or included in product evidence. Default each of these to no.

Interest in another session is not consent. A browser selection, a successful
render, or a verbal "looks good" is not authorization to retain or reuse a
file.
