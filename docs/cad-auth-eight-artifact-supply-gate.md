# CAD Auth bundled eight-artifact supply gate

Status: source-only proposal; no supply, private read, review or runtime authority.
Parent: PR #410, main commit `1fa92cf168743987bec44b6eca0b88ace72973b4`.
The parent packet remains unchanged. This successor provides one future supply
approval covering the complete eight-artifact schedule instead of eight separate
supply approvals. Existing category private-read templates remain historical
requirements; this supply phrase does not activate them.

## Complete bundle

Each category requires its own dedicated JSON receipt named `<category>.json`.
The JSON packet repeats the parent's exact required fields, source system,
custodian role, independent reviewer role, allowed evidence, retention and stop
conditions. Public field names describe the contract; they are not key listings
obtained from private files.

| Category | Existing evidence required |
| --- | --- |
| concreteProviderRuntimeBinding | Installation and provider-binding receipts plus reviewed adapter digest |
| executableCollectorCommand | Disabled-card and collector-source review receipts; no card issuance |
| restrictedSyntheticCohortReceipt | Synthetic cohort ownership attestations |
| custodyReviewerReceipt | Custodian, independent reviewer and restricted-store attestations |
| durableConsumedRunLedger | Prior atomic consumption and stop/unknown qualification |
| installedRouteBodyObserver | Prior installation, earliest boundary and buffering coverage |
| lateGrantObserver | Prior installation and late-grant denial attestations |
| immutableTargetRecheckReceipt | Matching candidate, immutable deployment, source digest and timestamp |

## Preparing the next human decision

1. The custodian must provide a complete private supply schedule with exactly one
   assignment per category. Each assignment names category, exact receipt
   filename, source system, custodian, independent reviewer, allowed evidence
   source, prior evidence approval reference, restricted store reference,
   retention duration and deletion owner. All fields are mandatory. Reviewers
   must be distinct from custodians, both per category and for the bundle.
2. Bind that complete schedule to the candidate commit and this packet. Resolve
   every phrase placeholder privately, including the schedule reference and
   SHA-256 digest, packet digest, bundle roles, store, duration, deletion owner
   and explicit UTC approval window. A reference alone cannot replace a complete
   reviewed schedule. This source-only tool neither reads nor hashes a private
   schedule. If preparing the schedule requires private reads, obtain a separate
   bounded approval first. Never discover ignored local candidates.
3. Present the resolved phrase and complete schedule together for one human
   supply approval. Missing, blank, placeholder, stale or mismatched fields stop
   the whole bundle. The committed template and passing tests grant no authority.
4. After that future approval, custodians may supply all eight artifacts from
   previously approved evidence within the named retention boundary. No private
   receipt read or private review is authorized by supply. If assembly requires
   such a read, stop for a separate gate. No partial acceptance, extra category,
   substitution, new collection, retry or second run is permitted. Missing
   evidence requires a separate proposal.
5. Independently review provenance and required fields only under a separate
   private-review approval. After all eight artifacts are supplied and reviewed,
   request the unchanged source-set private-read gate. Public release of any
   derived opaque reference, digest, byte count or disposition still requires the
   separate sanitized-projection approval.

## Exact future approval template

The authoritative template is
`preparation.futureApprovalGates.bundledArtifactSupply.exactPhraseTemplate` in
[cad-auth-eight-artifact-supply-gate.json](cad-auth-eight-artifact-supply-gate.json).
All `phraseFields` and unresolved category assignment fields remain null.
No completed approval phrase is generated by this packet. It is a proposal,
not an approval parser, executable command card or receipt processor.

## Stop and privacy boundaries

Stop on any missing category or required field, malformed or symlinked receipt,
duplicate source digest, unassigned or non-independent reviewer, unapproved
source evidence, undefined retention, stale target, mismatched digest, expired
approval window, unresolved placeholder or need for a prohibited action.
Source fixtures never prove installation or runtime behavior.

No private receipt values, local private paths, top-level key listings, secrets,
provider/runtime values, upload sessions, request bodies, private CAD or live
evidence are committed. The bundle authorizes no private reads or discovery,
provider/env/resource/billing changes, upload-session issuance, production upload
activation, body admission/read, conversion, Sandbox dispatch, live evidence,
runtime activation, executable command-card issuance, external messages, retry,
second run, real-user commercialization or commercial-readiness claim.
Previous approvals cannot be reused. Retention must cover the schedule, receipts
and private derivatives, with duration and deletion owner specified before use.
